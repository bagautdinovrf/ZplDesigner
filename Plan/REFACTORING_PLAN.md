# Реорганизация QtZpl Designer: оставшиеся работы

Дата: 22 октября 2026 года. В плане только невыполненные задачи. Выполненное
удалено: этапы R0–R5 и R7 реорганизации (`14e22bd`), пакеты L0–L7 для QtZpl
и этап 1 адаптации (`5f10789`), этап 2 «один владелец семантики команд ZPL»
(`effdd2d`, Designer 1.9.0, QtZpl 0.4.0). Подробности — в истории git и README.

Правила выполнения работ: [AGENTS.md](../AGENTS.md). Текущее поведение приложения: [README.md](../README.md).

Пути в примерах и команды указаны относительно корня соответствующего репозитория.

## 1. Неизменяемые требования

- Qt 6.11 или новее. Современный C++ согласно AGENTS.md и текущему CMake: MSVC `/std:c++latest` с метаданными CXX23; для остальных компиляторов — установленная проектом версия стандарта.
- Каждое превью строится через актуальные исходники соседней `../qt-zpl`. Модель библиотеки остаётся доступной редактору только для чтения.
- Координаты и размеры документа — printer dots. Zoom, тема, экранный DPI и расположение панелей не изменяют экспортируемую геометрию.
- Неподдерживаемый и неоднозначный ZPL, неизвестные команды и несколько этикеток сохраняются. Source mode остаётся полноценным способом работы.
- Исходные токены, комментарии, порядок и настройки ZPL сохраняются в уже поддерживаемых сценариях. Перенос не должен превращаться в нормализацию всех импортированных файлов.
- `.qtzpl` сохраняет применённый документ и неприменённый текст отдельно. Значения плейсхолдеров остаются данными текущей сессии.
- Ошибочная операция не оставляет частично изменённый документ. Неудачное открытие или сохранение не портит текущий документ, путь и признак изменения.
- Один законченный жест соответствует одной операции отмены. Отдельная текстовая история редактора ZPL и маршрутизация Ctrl+Z по фокусу сохраняются.
- Видимость на холсте и участие в печати остаются разными свойствами. Декорации редактора не попадают в PNG и печать.
- Оформление использует QPalette, постоянный QProxyStyle, QPainter и делегаты, без QSS. Переключение темы сохраняет геометрию, шрифты, курсор и состояние редакторов.
- Производственные INI не копируются в fixtures. Растровая приёмка опирается на принятые Labelary-эталоны, а не на изображения go-zpl.

## 2. R6. Типизировать содержимое элементов

Сейчас `Element` ([design_document.hpp](../src/core/design_document.hpp)) — плоская
структура с полями всех разновидностей объектов. Legacy `.qtzpl` и clipboard
сохраняют неактивные параметры разновидностей кодов: перевод только активного
содержимого в variant потеряет эти значения. Поэтому миграция явно хранит
неактивные настройки и обновляет codecs вместе с каждым типом; временная
вторая модель постоянно не поддерживается.

- [ ] Выделить общие свойства: UUID, группа, имя, положение, блокировка, видимость, участие в печати и данные сохранения исходника.
- [ ] Спроектировать отдельные структуры содержимого текста, изображения, таблицы, фигур и разновидностей штрихкодов; использовать `std::variant` либо столь же явную композицию.
- [ ] Сохранить чтение прежнего формата `.qtzpl` и clipboard через адаптеры, не сериализовать числовой индекс variant как постоянный формат.
- [ ] Явно решить судьбу неактивных параметров при смене типа: плоская модель сейчас может сохранять параметры прежнего штрихкода. Не терять их молча.
- [ ] Переносить один класс элементов за раз, синхронно обновляя операции, валидацию, кодеки и тесты совместимости.
- [ ] Удалять временные адаптеры после завершения миграции; не поддерживать две независимые модели постоянно.

**Готово, когда:** все существующие типы и старые проекты поддержаны; source metadata, изображения, таблицы, группы и clipboard проходят round trip; не относящиеся к типу свойства не могут случайно попасть в его обработчик.

Опора: структуры штрихкодов удобно повторить по типизированным параметрам
QtZpl (`FieldSettings::resolvedBarcode`, `ResolvedBarcode`), из которых импорт
уже читает значения. Сериализатор `serializeElement()` пишет параметры
по позициям и остаётся в Designer.

Организация: один владелец модели и сериализации; самостоятельное ревью
совместимости. Одновременная миграция общего заголовка несколькими агентами
не планируется.

| Контракт | Сценарии приёмки | Отправная точка |
|---|---|---|
| История | Жест/групповая операция — один undo; redo сохраняет ID, геометрию, группы и source metadata; ошибка/no-op не меняет историю | `test_session.cpp`, `test_session_operations.cpp`, `test_canvas.cpp` |
| Операции | Правила по типу элемента, отказ и no-op | `test_document_operations.cpp` |
| Сохранение | Старые `.qtzpl`, отдельный pending source, recovery, clean-state, ошибка записи и открытия | `test_projects.cpp`, `test_session.cpp` |
| ZPL без потерь | Неизвестные команды, несколько этикеток, комментарии и настройки вокруг изменённого поля, escaping, байты изображений | `test_document.cpp`, `test_extended_zpl.cpp`, `test_milk_import.cpp`, `test_barcode_semantics.cpp` |
| Clipboard | Вставка и копирование групп, таблиц, кодов, EAC | `test_editing_features.cpp`, `test_table_barcodes.cpp`, `test_eac.cpp` |
| UI | Mixed properties, смена типа штрихкода, выделение | `test_editor_panels.cpp`, `test_window.cpp` |

Названия файлов обозначают область поиска, а не утверждение о полном покрытии.
Сначала читать имеющиеся сценарии, затем добавлять только отсутствующие
проверки контрактов.

## 3. Прочие открытые задачи

- [ ] **Проверка версии QtZpl в Designer.** `CMakeLists.txt` вызывает
  `find_package(QtZpl CONFIG REQUIRED)` без версии, а при сборке из
  `../qt-zpl` версия не проверяется вовсе. Несовместимость (например,
  смена ABI в 0.4.0) проявляется только ошибкой компиляции.
- [ ] **Бюджет промежуточных растров.** У QtZpl нет такого бюджета, поэтому
  `validateParsed()` ([document_validation.cpp](../src/core/document_validation.cpp))
  сам оценивает размеры временных растров полей. Когда бюджет появится
  в библиотеке, оценки удалить.
- [ ] **Открытые расхождения с Labelary в QtZpl** (ожидаемые падения
  в `../qt-zpl/tests/golden/barcode-semantics/README.md`): подпись EAN над
  кодом, подписи `^B2`/`^BA` с контрольной цифрой, Aztec с размером 0.
  Исправляются в QtZpl отдельной задачей; после этого проверить, какие файлы
  Designer перестают уходить в режим исходника. Старт/стоп Codabar из `^BK`
  сделан в QtZpl 0.5.0 и Designer 1.10.0.

## 4. Проверка

Связанные изменения выполняются пакетом, затем запускаются относящиеся к ним
проверки (`ctest -R` по затронутым наборам). Финальная проверка законченного
этапа на Windows:

```text
py -3 tools/build_helper.py all --clean --config Debug
```

Все временные материалы — в `build_agent/`, журналы — в `build_agent/logs/`.
Каталоги Qt Creator не используются.
